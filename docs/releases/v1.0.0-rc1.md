# OCHP v1.0.0-rc1 Release Notes

## Release Type

Release Candidate for staging validation. Do not treat as final production release until manual UAT and deployment readiness gates pass.

## New Features

- Identity and access management with registration approval lifecycle.
- Secure role and facility assignment by Super Admin.
- CHP referral submission and facility workflow tracking.
- Workflow metadata/action engine for referral progression.
- CHP Directory management through secure CHP update path.
- Coverage Areas tracking independent from CHP account active status.
- Reports, exports, audit views, and operational documentation.

## Architecture

- Static frontend deployed through Vercel or equivalent static host.
- Supabase Auth for identity.
- Supabase Postgres with RLS, secure views, and secure RPCs.
- Workflow command behavior driven by database metadata.
- Operational runbooks for deployment, rollback, backup, restore, monitoring, and incident response.

## Security

- RLS enabled for protected data paths.
- Secure RPC framework for IAM, referral workflow, CHP, and coverage updates.
- Public execute revoked for sensitive RPCs and granted only as appropriate.
- CSP and security headers configured in `vercel.json`.
- Frontend tests prohibit service-role key material.

## Known Issues

See `KNOWN_ISSUES.md`.

Summary:

- Live Supabase smoke tests are manual for RC1.
- Browser export and notifications require manual UAT.
- Backup restore rehearsal is required before production go-live.
- No npm lockfile exists yet.

## Breaking Changes

- Coverage status is stored in `coverage_areas` and no longer derives from or modifies CHP active status.
- Deployments must apply all migrations through `20260706_000019_coverage_areas.sql` before RC1 validation.

## Upgrade Notes

1. Apply pending Supabase migrations in order.
2. Deploy static frontend artifact from the RC commit.
3. Verify `config.js` points to the staging Supabase project.
4. Run UAT packs under `docs/uat/`.
5. Review `KNOWN_ISSUES.md` and `docs/RISK_REGISTER.md` before go/no-go.
